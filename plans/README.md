# Animation improvement plans

Generated by `improve-animations` against commit `63c0a17`. Bar: Emil Kowalski's
design-engineering philosophy + Apple's *Designing Fluid Interfaces*. Personality
target: **crisp operational dashboard** — motion should be quiet, fast, and
purposeful.

Each plan is self-contained: exact file paths, current code, target values, and a
feel-check. Any agent (or a cheaper model) can execute one without further context.

## Recommended execution order

Do the two HIGH plans first — they carry the most feel per line changed and define
the tokens everything else references:

1. **002** — easing tokens (foundation; 005, 006, 010 reference `easings.easeOut`).
2. **001** — remove decorative hover motion (also deletes a chunk of the shorthand
   usage that 008 would otherwise flag).
3. **003** — reduced-motion (introduces the `useReducedMotion()` pattern that 005 and
   007 reuse).
4. **004** — spring retune (independent; safe any time after 002).
5. **005** — Card opt-in entrance (depends on 002 for the curve; benefits from 003).
6. **006**, **007** — small fixes (depend on 002/003 for shared tokens/hook).
7. **009**, **010** — additive polish (missed opportunities); do last.
8. **008** — profile *after* 001 + 005 land, since they remove much of the shorthand
   usage; may close as no-change-needed.

## Dependencies

- **002 is the foundation**: 005, 006, 010 import `easings.easeOut`. If you run them
  before 002, use the inline fallback each plan notes.
- **003 introduces `useReducedMotion()`**: 005 and 007 reuse the import in the same
  files; landing 003 first avoids duplicate import churn.
- **008 depends on 001 + 005** having landed (they remove shorthand sites), then
  re-profile.

## Not included (already correct)

- Radix/shadcn `animate-in/out` primitives (dialog, dropdown, select, tooltip,

  Left as-is.
- Message-list arrival (`Messages.tsx:1080`) — already staggered with
  `AnimatePresence mode="popLayout"`. Not re-litigated.
